# CSSU Task Activity Monitoring System — Web Edition

This folder contains a browser-based conversion of the supplied Tkinter desktop prototype. The original `cssu_monitor.py` is retained as a reference; the deployed web application runs from `app.py`.

## Included functionality

- Individual administrator and staff sign-in, with role-based access.
- Daily task logging: date, category/task, quantity, status, priority, start/end time, details, issue notes and endorsements.
- Monthly dashboard: task totals, status counts and staff task counts (admin view); open delegated assignment count.
- Administrator task delegation with staff assignment, due date, priority and instructions.
- Staff assignment inbox and progress updates (`Assigned`, `In Progress`, `Completed`, `Unable to Complete`). A note is required for completed or unable-to-complete updates.
- Staff account creation and activation/deactivation.
- Category and task-option maintenance.
- Audit log and CSV export (opens in Excel; CSV is used instead of legacy `.xls`).
- PostgreSQL support for hosted multi-user use; SQLite is retained as a local development default.

Delegated assignments remain separate from daily task-output logs to avoid double-counting. The starter app does not implement supervisor verification of completed assignments, electronic signatures, password reset, or formal appraisal scoring.

## Run locally

Python 3.10+ is recommended.

```bash
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export SECRET_KEY="replace-with-a-long-random-secret"
export ADMIN_PASSWORD="use-a-unique-strong-password"
python app.py
```

On Windows, use `$env:SECRET_KEY="..."` and `$env:ADMIN_PASSWORD="..."` in PowerShell. Open `http://127.0.0.1:5000`.

On first launch, the database and default CSSU categories/task options are created. The first administrator username is `admin`; its password is the value of `ADMIN_PASSWORD`. If `ADMIN_PASSWORD` is not set on first launch, the starter password `ChangeMe123!` is used and a warning is logged. **Always set a unique strong `ADMIN_PASSWORD` before first deployment.** Existing databases are not reset when the variable changes. Change the password after initial sign-in.

New staff accounts receive the temporary password `TempPass123!`; require them to change it immediately. Password changes require at least 12 characters.

## Deploy to Render

1. Create a private GitHub repository and upload the contents of this folder.
2. In Render, choose **New → Blueprint** and connect that repository. Render reads `render.yaml` to configure the web service and PostgreSQL database.
3. When prompted, set `ADMIN_PASSWORD` to a unique strong password. `SECRET_KEY` is generated by the blueprint. Keep both private; never commit them to Git.
4. Review the selected plans and deploy. Render will provide a public `onrender.com` URL.
5. Sign in as `admin`, change the password, create individual staff accounts, and test each role before inviting users.
6. Confirm that the database plan's persistence, backup/restore options, and cost are appropriate before entering operational records.

The included blueprint uses a free web-service instance and a paid `basic-256mb` PostgreSQL plan. The database is intentionally paid: Render Free Postgres expires 30 days after creation, has no backups, and is unsuitable for storing continuing operational records. The free web service can sleep after 15 minutes without traffic and may take about a minute to wake. Before official use, confirm the database plan, backup/restore capability, monitoring and recovery plan with CSSU/IT. You can change the web-service plan if uninterrupted availability is required.

## Security and operational cautions

- This is a functional starter conversion, not a security certification. Arrange CSSU/organizational IT and privacy review before real deployment.
- Use HTTPS (Render provides HTTPS for its service URL), strong unique passwords, private repository access, restricted administrator accounts and least-privilege access.
- Do not enter patient names, patient numbers, diagnoses or other patient-identifying information. Use task-level operational descriptions only.
- Do not use task counts alone as a formal appraisal score. Leadership should approve a rubric that accounts for complexity, quality, timeliness, workload, teamwork and safety compliance.
- Configure and test database backups and restoration. Do not rely on a developer's local SQLite file as the hosted database backup.
- The audit log records application actions, but this starter is not tamper-proof and is not a substitute for an organization-wide audit system.
- The application stores timestamps in UTC for audit/delegation fields; task dates are entered as calendar dates.
- No password reset or email notification workflow is included yet. Administrators must handle account provisioning securely.

## Technical notes

- Flask + Flask-Login + Flask-WTF + Flask-SQLAlchemy.
- PostgreSQL via `DATABASE_URL` (Render blueprint injects it); SQLite fallback for local testing.
- Run command: `gunicorn app:app --workers 1 --threads 4 --timeout 120`.
- Health endpoint: `/login`.
